# Conversation Manager v0.7.5

本版本补上「ChatGPT 同步反复超时」的最后一个死角：为浏览器扩展引入代码指纹机制，让「版本号没变但运行代码没更新」的陈旧扩展无处遁形——同步出问题时直接告诉你病因与解法，而不是笼统的「网络较慢」。

## 扩展代码指纹：同版本更新也能自动重载

- 背景：实机排查发现一类顽固故障——扩展 Service Worker 仍在运行内存里的旧代码，但扩展版本号与磁盘文件一致（自愈覆写不改变版本号时就会出现）。纯版本比对永远发现不了这种漂移，旧代码缺少全部超时防护，一旦 ChatGPT 标签页被 Chrome 冻结，串行转发队列就会永久卡死，之后每次同步都等满 5 分钟才报「同步或操作超时」。
- 扩展现在在 Service Worker 启动时对自身三个代码文件（background.js / bridge-core.js / content.js）计算 SHA-256 指纹，随每次轮询上报桌面端；进程生命周期内只算一次，零轮询开销。
- 桌面端对磁盘上的最新扩展文件计算同一指纹并比对：发现「运行代码落后于磁盘」即下发硬重载提示，扩展在 1.5 秒内的下一次轮询自动重启加载新代码——**同版本号的内容修补从此也能自动升级**，防风暴守卫（同一身份最多提示 2 次）原样保留。

## 同步超时智能诊断：一句话直达病因

- 桥接命令超时而扩展明明在线时（轮询 15 秒内有心跳），桌面端自动判定扩展是否为无法自动升级的旧代码：
  - 判定成立时，错误提示从「浏览器可能正在休眠或网络较慢」换成明确的「**扩展运行的不是最新代码，请在 chrome://extensions 重新加载该扩展（或重启浏览器）**」；
  - 判定不成立（指纹一致 / 无法判定）时保持原有提示，不误报。
- 判定依据（上报版本、双方指纹、陈旧类别）同步写入运行日志，远程排查有迹可循。

## 稳健性

- 指纹计算失败时上报明确的 `hash-unavailable` 占位标记并继续轮询，绝不阻塞同步通道（3 秒竞速兜底，配专项测试钉住）。
- 新增逻辑在三端均有单元测试覆盖：扩展指纹算法与上报（含失败降级）、桥接服务的指纹透传与非法值防护、桌面端陈旧判定（含「同版本内容漂移」「旧到没有指纹头」等边界）、渲染层新错误文案的中英文对照。
- 全量回归：扩展 20 项、桥接服务 16 项、桌面 54 项测试全部通过；ESLint 与中英文案审计通过。

## 升级说明

- **仍偶尔看到「同步或操作超时」的用户**：安装本版本后，请在 `chrome://extensions` 中对 Conversation Manager Bridge 扩展点击一次「重新加载」（或重启浏览器）——这是摆脱旧代码的最后一步人工操作。此后代码指纹机制接管一切：桌面端更新扩展文件后，扩展会自动重载，同版本修补也不例外，全程零人工。
- **从 v0.7.4 正常升级的用户**：无需任何操作，桌面端与扩展会自动完成指纹机制对接；日后若再遇到超时，提示会直接告诉你要不要重载扩展。
